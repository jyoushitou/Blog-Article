# mcmod

本篇记录 NeoForge 1.21.1 下从零添加一个自定义方块的完整流程，包含方块本体、物品形态、翻译、注册、创造物品栏、放置资源与掉落物。
示例：modid = `tutorial`，注册名 = `ruby_block`，方块类 `RubyBlock`。
目录约定：Java 在 `src/main/java/...`，资源在 `src/main/resources/assets/tutorial/...`，数据在 `src/main/resources/data/tutorial/...`。
与 Fabric 最大的区别：注册统一走 `DeferredRegister` + 事件总线，没有 `fabric.mod.json`，改用 `META-INF/neoforge.mods.toml`。

# 方块的添加

先写方块类，直接 `new Block(properties)` 也行，需要自定义行为时才继承：

```java src/main/java/com/example/tutorial/block/RubyBlock.java
package com.example.tutorial.block;

import net.minecraft.core.BlockPos;
import net.minecraft.network.chat.Component;
import net.minecraft.world.InteractionResult;
import net.minecraft.world.entity.player.Player;
import net.minecraft.world.level.Level;
import net.minecraft.world.level.block.Block;
import net.minecraft.world.level.block.state.BlockState;
import net.minecraft.world.phys.BlockHitResult;

public class RubyBlock extends Block {
    public RubyBlock(Properties properties) {
        super(properties);
    }

    // 1.21.1 里空手右键走 useWithoutItem，手持物品右键则走 useItemOn
    @Override
    protected InteractionResult useWithoutItem(BlockState state, Level level, BlockPos pos,
                                               Player player, BlockHitResult hit) {
        if (!level.isClientSide) {
            player.displayClientMessage(Component.literal("你摸了一下红宝石块"), false);
        }
        return InteractionResult.SUCCESS;
    }
}
```

方块属性用 `BlockBehaviour.Properties`：

```java
import net.minecraft.world.level.block.Block;
import net.minecraft.world.level.block.SoundType;
import net.minecraft.world.level.material.MapColor;

public static final Block.Properties RUBY_PROPERTIES = Block.Properties.of()
        .mapColor(MapColor.COLOR_RED)     // 地图颜色
        .strength(3.0f, 6.0f)             // (硬度, 抗爆)，硬度决定挖掘时间
        .sound(SoundType.METAL)
        .requiresCorrectToolForDrops();   // 必须用正确工具挖才掉落
```

要点：

- NeoForge 里是 `requiresCorrectToolForDrops()`（Fabric 叫 `requiresTool()`），而且它本身就参与掉落判定。
- 该方法只保证“用对工具才掉落”，具体工具类型还要靠 `mineable/pickaxe` 标签指定。
- 不写它时，任何工具/空手都能挖并掉落。

# 翻译的添加

语言文件路径和 Fabric 一样：

- `src/main/resources/assets/tutorial/lang/zh_cn.json`
- `src/main/resources/assets/tutorial/lang/en_us.json`

```json src/main/resources/assets/tutorial/lang/zh_cn.json
{
  "block.tutorial.ruby_block": "红宝石块",
  "item.tutorial.ruby_block": "红宝石块",
  "itemGroup.tutorial.main": "红宝石模组"
}
```

```json src/main/resources/assets/tutorial/lang/en_us.json
{
  "block.tutorial.ruby_block": "Ruby Block",
  "item.tutorial.ruby_block": "Ruby Block",
  "itemGroup.tutorial.main": "Ruby Mod"
}
```

要点：

- key 规则固定：`block.<modid>.<注册名>`、`item.<modid>.<注册名>`。
- 同一个方块同时有 Block 和 BlockItem，建议两条都写，否则某些界面会直接显示 `block.tutorial.ruby_block`。
- 语言文件是标准 JSON：不能有注释、不能有多余逗号，编码用 UTF-8。
- 只写 `zh_cn.json` 的话，切到英文环境会回退成翻译 key，所以 `en_us.json` 最好一起给。

# 方块的注册

NeoForge 用 `DeferredRegister` 承包，注册动作挂在事件总线上。先建注册器，再 `register`。

```java src/main/java/com/example/tutorial/ModBlocks.java
package com.example.tutorial;

import com.example.tutorial.block.RubyBlock;
import net.minecraft.world.item.BlockItem;
import net.minecraft.world.item.Item;
import net.minecraft.world.level.block.Block;
import net.minecraft.world.level.block.SoundType;
import net.minecraft.world.level.material.MapColor;
import net.neoforged.bus.api.IEventBus;
import net.neoforged.neoforge.registries.DeferredBlock;
import net.neoforged.neoforge.registries.DeferredItem;
import net.neoforged.neoforge.registries.DeferredRegister;

public class ModBlocks {
    // 方块注册器，createBlocks 内部绑定 Registries.BLOCK
    public static final DeferredRegister.Blocks BLOCKS =
            DeferredRegister.createBlocks(TutorialMod.MOD_ID);
    // 物品注册器，createItems 内部绑定 Registries.ITEM
    public static final DeferredRegister.Items ITEMS =
            DeferredRegister.createItems(TutorialMod.MOD_ID);

    // 注册方块本体
    public static final DeferredBlock<Block> RUBY_BLOCK = BLOCKS.register("ruby_block",
            () -> new RubyBlock(Block.Properties.of()
                    .mapColor(MapColor.COLOR_RED)
                    .strength(3.0f, 6.0f)
                    .sound(SoundType.METAL)
                    .requiresCorrectToolForDrops()));

    // 注册物品形态，registerSimpleBlockItem 会按方块名生成同名 BlockItem
    public static final DeferredItem<BlockItem> RUBY_BLOCK_ITEM =
            ITEMS.registerSimpleBlockItem(RUBY_BLOCK);

    public static void register(IEventBus modEventBus) {
        BLOCKS.register(modEventBus);
        ITEMS.register(modEventBus);
    }
}
```

`registerSimpleBlockItem(RUBY_BLOCK)` 等价于手写：

```java
ITEMS.register("ruby_block",
        () -> new BlockItem(RUBY_BLOCK.get(), new Item.Properties()));
```

模组入口（注意 modid 由构造参数注入，事件总线也是注入进来的）：

```java src/main/java/com/example/tutorial/TutorialMod.java
package com.example.tutorial;

import net.neoforged.bus.api.IEventBus;
import net.neoforged.fml.common.Mod;

@Mod(TutorialMod.MOD_ID)
public class TutorialMod {
    public static final String MOD_ID = "tutorial";

    public TutorialMod(IEventBus modEventBus) {
        ModBlocks.register(modEventBus);
        ModCreativeTabs.register(modEventBus);
    }
}
```

对应 `src/main/resources/META-INF/neoforge.mods.toml`：

```toml src/main/resources/META-INF/neoforge.mods.toml
modLoader = "javafml"
loaderVersion = "[4,)"
license = "MIT"

[[mods]]
modId = "tutorial"
version = "1.0.0"
displayName = "Tutorial Mod"

[[dependencies.tutorial]]
modId = "neoforge"
type = "required"
versionRange = "[21.1.0,)"
ordering = "NONE"
```

注意：

- 注册名必须小写、只用 `a-z0-9_`，否则启动直接报非法 ResourceLocation。
- `DeferredRegister` 是“延迟注册”，对象在注册事件触发后才真正创建，取值要用 `.get()`。

# 物品栏的添加

这里的“物品栏”指方块的 **物品形态（BlockItem）**——没有它，方块只能靠 `/setblock` 出现，无法拿在手上。

上一节已用 `registerSimpleBlockItem` 一起注册，这里补充可调项：

```java
ITEMS.register("ruby_block", () -> new BlockItem(ModBlocks.RUBY_BLOCK.get(),
        new Item.Properties()
                .stacksTo(64)            // 默认就是 64
                .rarity(Rarity.UNCOMMON) // 稀有度，影响物品名颜色
));
```

- 只注册“纯物品”时：`ITEMS.register("xxx", () -> new Item(new Item.Properties()));`
- 想让物品栏里的方块正常显示，必须有对应的**物品模型**（见“物品的放置”）。
- 想加提示文字，让 BlockItem 子类覆写 `appendHoverText`。

# 创造物品栏的添加

两种做法，先看“塞进原版标签页”，NeoForge 用 `BuildCreativeModeTabContentsEvent`：

```java src/main/java/com/example/tutorial/ModCreativeTabs.java
package com.example.tutorial;

import net.minecraft.world.item.CreativeModeTabs;
import net.neoforged.bus.api.IEventBus;
import net.neoforged.neoforge.event.BuildCreativeModeTabContentsEvent;

public class ModCreativeTabs {

    public static void register(IEventBus modEventBus) {
        // 监听原版标签页构建事件
        modEventBus.addListener(ModCreativeTabs::addToVanillaTabs);
        // 顺便把自建标签页注册器挂上总线
        ModTabs.TABS.register(modEventBus);
    }

    private static void addToVanillaTabs(BuildCreativeModeTabContentsEvent event) {
        // 追加到「建筑方块」标签页
        if (event.getTabKey() == CreativeModeTabs.BUILDING_BLOCKS) {
            event.accept(ModBlocks.RUBY_BLOCK_ITEM);
        }
    }
}
```

也可以自建专属标签页：

```java src/main/java/com/example/tutorial/ModTabs.java
package com.example.tutorial;

import net.minecraft.core.registries.Registries;
import net.minecraft.network.chat.Component;
import net.minecraft.world.item.CreativeModeTab;
import net.minecraft.world.item.ItemStack;
import net.neoforged.neoforge.registries.DeferredHolder;
import net.neoforged.neoforge.registries.DeferredRegister;

public class ModTabs {
    public static final DeferredRegister<CreativeModeTab> TABS =
            DeferredRegister.create(Registries.CREATIVE_MODE_TAB, TutorialMod.MOD_ID);

    public static final DeferredHolder<CreativeModeTab, CreativeModeTab> TUTORIAL_TAB =
            TABS.register("main", () -> CreativeModeTab.builder()
                    .title(Component.translatable("itemGroup.tutorial.main"))
                    .icon(() -> new ItemStack(ModBlocks.RUBY_BLOCK_ITEM.get())) // 图标只能一个物品
                    .displayItems((params, output) ->
                            output.accept(ModBlocks.RUBY_BLOCK_ITEM.get()))
                    .build());
}
```

要点：

- 自建物品栏的标题翻译 key = `itemGroup.tutorial.main`，要和 lang 文件对应。
- 图标只能是单个 `ItemStack`，不会随内容变化。
- 事件监听要用 `modEventBus.addListener(...)`，和游戏事件总线（`NeoForge.EVENT_BUS`）不是同一个。

# 物品的放置

方块能被右键放置，靠的是 BlockItem 自带的放置逻辑，一般不用写代码。需要保证三样资源齐全：

1）物品模型 `assets/tutorial/models/item/ruby_block.json`：

```json src/main/resources/assets/tutorial/models/item/ruby_block.json
{
  "parent": "tutorial:block/ruby_block"
}
```

2）方块模型 `assets/tutorial/models/block/ruby_block.json`（`cube_all` 会自动套用同名贴图）：

```json src/main/resources/assets/tutorial/models/block/ruby_block.json
{
  "parent": "minecraft:block/cube_all",
  "textures": {
    "all": "tutorial:block/ruby_block"
  }
}
```

3）方块状态 `assets/tutorial/blockstates/ruby_block.json`：

```json src/main/resources/assets/tutorial/blockstates/ruby_block.json
{
  "variants": {
    "": { "model": "tutorial:block/ruby_block" }
  }
}
```

贴图放 `src/main/resources/assets/tutorial/textures/block/ruby_block.png`，尺寸建议 16×16 或其整数倍。

限制放置条件时覆写 `canSurvive`：

```java
@Override
public boolean canSurvive(BlockState state, LevelReader level, BlockPos pos) {
    return level.getBlockState(pos.below()).is(Blocks.DIRT);
}
```

想让方块按玩家朝向旋转，需要在方块类里加 `FACING` 属性并实现 `getStateForPlacement()`，同时 blockstates 按 `facing` 写多个 variant。

# 掉落物的设置

掉落物由**战利品表**决定（1.21 起路径是单数 `loot_table`）：

`src/main/resources/data/tutorial/loot_table/blocks/ruby_block.json`

```json src/main/resources/data/tutorial/loot_table/blocks/ruby_block.json
{
  "type": "minecraft:block",
  "pools": [
    {
      "rolls": 1,
      "entries": [
        {
          "type": "minecraft:item",
          "name": "tutorial:ruby_block"
        }
      ],
      "conditions": [
        {
          "condition": "minecraft:survives_explosion"
        }
      ]
    }
  ]
}
```

- `type: minecraft:block` 是方块专用类型；`rolls` 是抽取次数；`survives_explosion` 表示被爆炸破坏时不掉落。
- 想随机数量 / 受时运影响：

```json
{
  "type": "minecraft:item",
  "name": "tutorial:ruby_block",
  "functions": [
    { "function": "minecraft:set_count", "count": { "min": 1, "max": 3 } },
    {
      "function": "minecraft:apply_bonus",
      "enchantment": "minecraft:fortune",
      "formula": "minecraft:ore_drops"
    }
  ]
}
```

- 想“必须用正确工具才掉落”，靠 `requiresCorrectToolForDrops()` 加上工具标签：

```json src/main/resources/data/minecraft/tags/block/mineable/pickaxe.json
{
  "replace": false,
  "values": ["tutorial:ruby_block"]
}
```

（1.21 起标签路径是 `data/minecraft/tags/block/...`，1.20.4 及以前是 `tags/blocks/...`）

- 这些 JSON 也可以用 NeoForge 的数据生成（Datagen）来自动产出，减少手写错误；手写时**优先用战利品表**，数据驱动更好维护。

# 物品的配方

配方放在数据包路径：`src/main/resources/data/tutorial/recipe/`（1.21 起目录名是单数 `recipe`，1.20.4 及以前是 `recipes`）。
文件名随意，但要唯一；`result` 里写物品 id，`count` 通常省略（默认 1）。

## 有序合成（shaped）

九宫格用 `pattern` 画，每行一个字符串、每格一个字符，`key` 说明字符对应什么。
空格表示留空。

```json src/main/resources/data/tutorial/recipe/ruby_block.json
{
  "type": "minecraft:crafting_shaped",
  "category": "building",
  "pattern": ["RRR", "RRR", "RRR"],
  "key": {
    "R": {
      "item": "tutorial:ruby"
    }
  },
  "result": {
    "id": "tutorial:ruby_block",
    "count": 1
  }
}
```

要点：

- `pattern` 最多 3 个字符串，每个最多 3 字符。
- `key` 的值在 1.21 用 `{ \"item\": \"...\" }` 或 `{ \"tag\": \"...\" }`；旧版本直接写字符串 `\"tutorial:ruby\"`。
- `result` 在 1.21 用 `id` + `count`；1.20.4 及以前是 `item` 字段 + `count`。
- `category`（`building`/`misc`/`redstone`/`equipment`）只影响配方书里的分类，可省略。

## 无序合成（shapeless）

不讲究摆位，`ingredients` 是数组：

```json src/main/resources/data/tutorial/recipe/ruby_from_blocks.json
{
  "type": "minecraft:crafting_shapeless",
  "category": "misc",
  "ingredients": [
    { "item": "tutorial:ruby" },
    { "item": "tutorial:ruby" },
    { "item": "minecraft:gunpowder" }
  ],
  "result": {
    "id": "tutorial:ruby_block",
    "count": 1
  }
}
```

- `ingredients` 里放几个，就消耗几个；同一个物品 id 写几次就按几次算。

## 常用加工配方

按同一套结构，换个 `type` 即可：

```json
// 熔炉（烧炼）
{
  "type": "minecraft:smelting",
  "category": "blocks",
  "ingredient": { "item": "tutorial:ruby_ore" },
  "result": { "id": "tutorial:ruby", "count": 1 },
  "experience": 0.7,
  "cookingtime": 200
}
```

```json
// 高炉 / 烟熏炉 / 营火，写法一样，只改 type
{
  "type": "minecraft:blasting",
  "category": "blocks",
  "ingredient": { "item": "tutorial:ruby_ore" },
  "result": { "id": "tutorial:ruby", "count": 1 },
  "experience": 0.7,
  "cookingtime": 100
}
```

```json
// 切石机
{
  "type": "minecraft:stonecutting",
  "ingredient": { "item": "tutorial:ruby_block" },
  "result": { "id": "tutorial:ruby_slab", "count": 2 }
}
```

```json
// 锻造台：把模板+底料+附加料合成一件装备
{
  "type": "minecraft:smithing_transform",
  "template": { "item": "tutorial:ruby_upgrade_template" },
  "base": { "item": "minecraft:diamond_pickaxe" },
  "addition": { "item": "tutorial:ruby" },
  "result": { "id": "tutorial:ruby_pickaxe", "count": 1 }
}
```

## 要点

- `type` 必须是**已注册的配方类型 id**；写错不会报错，但配方直接不生效（游戏内用 JEI/REI 看不到）。
- `cookingtime` 单位是刻（tick），20 刻 = 1 秒；熔炉默认 200，高炉/烟熏炉 100。
- `experience` 是取出成品时给玩家的经验，范围一般 0.0 ~ 1.0。
- `ingredient`（加工类）用单个对象，`ingredients`（无序合成）用数组，别写混。
- 1.20.4 及以前把上面所有 `{ \"id\": ... }` 换成 `{ \"item\": ... }`，路径 `recipe` 换成 `recipes`。
- 这些 JSON 同样可用 NeoForge 的 Datagen（`RecipeProvider`）自动生成，避免手写 id 出错。

# 数据生成

前面的方块模型、物品模型、战利品表、配方、标签、翻译全都能用代码自动生成（Datagen），避免手写 JSON 出错。
一切挂在**模组事件总线**的 `GatherDataEvent` 上。

## 注册入口

```java src/main/java/com/example/tutorial/datagen/DataGenerators.java
package com.example.tutorial.datagen;

import com.example.tutorial.TutorialMod;
import net.neoforged.bus.api.SubscribeEvent;
import net.neoforged.fml.common.EventBusSubscriber;
import net.neoforged.neoforge.data.event.GatherDataEvent;

@EventBusSubscriber(modid = TutorialMod.MOD_ID, bus = EventBusSubscriber.Bus.MOD)
public class DataGenerators {

    @SubscribeEvent
    public static void gatherData(GatherDataEvent event) {
        var generator = event.getGenerator();
        var output = generator.getPackOutput();            // 输出目录
        var lookupProvider = event.getLookupProvider();    // 注册表查询
        var existingFileHelper = event.getExistingFileHelper();

        // ---- 客户端资源（assets：模型 / 语言）----
        generator.addProvider(event.includeClient(),
                new ModBlockStateProvider(output, existingFileHelper));
        generator.addProvider(event.includeClient(),
                new ModItemModelProvider(output, existingFileHelper));
        generator.addProvider(event.includeClient(), new ModLangProvider(output, "en_us"));
        generator.addProvider(event.includeClient(), new ModLangProvider(output, "zh_cn"));

        // ---- 服务端数据（data：战利品表 / 配方 / 标签）----
        generator.addProvider(event.includeServer(),
                new ModBlockLootTables(lookupProvider));
        generator.addProvider(event.includeServer(),
                new ModRecipeProvider(output, lookupProvider));
        generator.addProvider(event.includeServer(),
                new ModBlockTagsProvider(output, lookupProvider, existingFileHelper));
    }
}
```

要点：

- `includeClient()` / `includeServer()` 控制“只生成客户端资源”还是“只生成服务端数据”，按需拆开更省时间。
- 1.21.1 用 `@EventBusSubscriber(bus = EventBusSubscriber.Bus.MOD)`；旧版是 `@Mod.EventBusSubscriber`，别照抄。
- 生成的文件默认落在 `src/generated/resources`，要保证它被当成资源根目录（NeoGradle/MDK 默认已配好）。

## 方块模型（BlockStateProvider）

```java src/main/java/com/example/tutorial/datagen/ModBlockStateProvider.java
package com.example.tutorial.datagen;

import com.example.tutorial.ModBlocks;
import com.example.tutorial.TutorialMod;
import net.minecraft.data.PackOutput;
import net.neoforged.neoforge.client.model.generators.BlockStateProvider;
import net.neoforged.neoforge.common.data.ExistingFileHelper;

public class ModBlockStateProvider extends BlockStateProvider {
    public ModBlockStateProvider(PackOutput output, ExistingFileHelper exFileHelper) {
        super(output, TutorialMod.MOD_ID, exFileHelper);
    }

    @Override
    protected void registerStatesAndModels() {
        // 生成 blockstates/ruby_block.json + models/block/ruby_block.json
        simpleBlock(ModBlocks.RUBY_BLOCK.get());
    }
}
```

- `simpleBlock(...)` 会自动产出前面手写的 blockstates 和 cube_all 方块模型。
- 贴图仍需自己放到 `textures/block/ruby_block.png`（Datagen 不会画图）。

## 物品模型（ItemModelProvider）

```java src/main/java/com/example/tutorial/datagen/ModItemModelProvider.java
package com.example.tutorial.datagen;

import com.example.tutorial.ModBlocks;
import com.example.tutorial.TutorialMod;
import net.minecraft.data.PackOutput;
import net.neoforged.neoforge.client.model.generators.ItemModelProvider;
import net.neoforged.neoforge.common.data.ExistingFileHelper;

public class ModItemModelProvider extends ItemModelProvider {
    public ModItemModelProvider(PackOutput output, ExistingFileHelper exFileHelper) {
        super(output, TutorialMod.MOD_ID, exFileHelper);
    }

    @Override
    protected void registerModels() {
        // 生成 models/item/ruby_block.json，父模型指向方块模型
        basicItem(ModBlocks.RUBY_BLOCK_ITEM.get());
    }
}
```

- `basicItem(...)` 生成 `{"parent": "tutorial:block/ruby_block"}` 这类物品模型。
- 普通物品（没有方块模型）用它即可；需要自定义就手写或调 `withExistingParent(...)`。

## 战利品表（BlockLootSubProvider）

```java src/main/java/com/example/tutorial/datagen/ModBlockLootTables.java
package com.example.tutorial.datagen;

import com.example.tutorial.ModBlocks;
import net.minecraft.core.HolderLookup;
import net.minecraft.data.loot.BlockLootSubProvider;
import net.minecraft.world.flag.FeatureFlags;
import net.minecraft.world.level.block.Block;

import java.util.Set;

public class ModBlockLootTables extends BlockLootSubProvider {
    protected ModBlockLootTables(HolderLookup.Provider registries) {
        super(Set.of(), FeatureFlags.REGISTRY.allFlags(), registries);
    }

    @Override
    protected void generate() {
        // 自己掉落自己
        dropSelf(ModBlocks.RUBY_BLOCK.get());
    }

    @Override
    protected Iterable<Block> getKnownBlocks() {
        // 让校验器知道有哪些方块，缺表会报错提醒
        return ModBlocks.BLOCKS.getEntries().stream()
                .map(holder -> (Block) holder.get())
                ::iterator;
    }
}
```

- `dropSelf(block)` = 前面手写的 `loot_table/blocks/ruby_block.json`（掉自己）。
- 想让方块掉成别的物品，用 `createSilkTouchDispatchTable(...)`、`createOreDrop(...)` 等方法。

## 配方（RecipeProvider）

```java src/main/java/com/example/tutorial/datagen/ModRecipeProvider.java
package com.example.tutorial.datagen;

import com.example.tutorial.ModBlocks;
import com.example.tutorial.ModItems;
import net.minecraft.core.HolderLookup;
import net.minecraft.data.PackOutput;
import net.minecraft.data.recipes.RecipeCategory;
import net.minecraft.data.recipes.RecipeOutput;
import net.minecraft.data.recipes.RecipeProvider;
import net.minecraft.data.recipes.ShapedRecipeBuilder;

import java.util.concurrent.CompletableFuture;

public class ModRecipeProvider extends RecipeProvider {
    public ModRecipeProvider(PackOutput output, CompletableFuture<HolderLookup.Provider> registries) {
        super(output, registries);
    }

    @Override
    protected void buildRecipes(RecipeOutput recipeOutput) {
        // 3x3 红宝石 -> 红宝石块
        ShapedRecipeBuilder.shaped(RecipeCategory.BUILDING_BLOCKS, ModBlocks.RUBY_BLOCK.get())
                .pattern("RRR")
                .pattern("RRR")
                .pattern("RRR")
                .define('R', ModItems.RUBY.get())
                .unlockedBy("has_ruby", has(ModItems.RUBY.get())) // 配方书解锁条件
                .save(recipeOutput);
    }
}
```

- `ShapelessRecipeBuilder.shapeless(...)` 对应无序合成，`SimpleCookingRecipeBuilder.smelting(...)` 对应烧炼。
- `unlockedBy(...)` 决定配方何时在配方书出现，必须写，否则配方书里看不到。

## 标签（BlockTagsProvider）

```java src/main/java/com/example/tutorial/datagen/ModBlockTagsProvider.java
package com.example.tutorial.datagen;

import com.example.tutorial.ModBlocks;
import com.example.tutorial.TutorialMod;
import net.minecraft.core.HolderLookup;
import net.minecraft.data.PackOutput;
import net.minecraft.tags.BlockTags;
import net.neoforged.neoforge.common.data.BlockTagsProvider;
import net.neoforged.neoforge.common.data.ExistingFileHelper;

import java.util.concurrent.CompletableFuture;

public class ModBlockTagsProvider extends BlockTagsProvider {
    public ModBlockTagsProvider(PackOutput output,
                                CompletableFuture<HolderLookup.Provider> lookupProvider,
                                ExistingFileHelper existingFileHelper) {
        super(output, lookupProvider, TutorialMod.MOD_ID, existingFileHelper);
    }

    @Override
    protected void addTags(HolderLookup.Provider provider) {
        // 用镐子挖
        tag(BlockTags.MINEABLE_WITH_PICKAXE).add(ModBlocks.RUBY_BLOCK.get());
        // 至少需要铁镐才掉落（可选）
        tag(BlockTags.NEEDS_IRON_TOOL).add(ModBlocks.RUBY_BLOCK.get());
    }
}
```

- `MINEABLE_WITH_PICKAXE` 就对应前面手写的 `mineable/pickaxe` 标签。
- `NEEDS_IRON_TOOL` 对应 `needs_iron_tool`，配合 `requiresCorrectToolForDrops()` 才是“铁镐以下不掉落”。

## 语言（LanguageProvider）

```java src/main/java/com/example/tutorial/datagen/ModLangProvider.java
package com.example.tutorial.datagen;

import com.example.tutorial.TutorialMod;
import net.minecraft.data.PackOutput;
import net.neoforged.neoforge.common.data.LanguageProvider;

public class ModLangProvider extends LanguageProvider {
    public ModLangProvider(PackOutput output, String locale) {
        super(output, TutorialMod.MOD_ID, locale); // locale: en_us / zh_cn
    }

    @Override
    protected void addTranslations() {
        add("block.tutorial.ruby_block", "Ruby Block");
        add("item.tutorial.ruby_block", "Ruby Block");
        add("itemGroup.tutorial.main", "Ruby Mod");
    }
}
```

- 构造里传不同 `locale` 就能各生成一份语言文件（中文那份把 value 换成中文）。
- `add("block.tutorial.ruby_block", "红宝石块")` 会自动生成对应 key。

## 运行

- IDEA 右侧 Gradle 面板执行 `runData`，或命令行 `./gradlew runData`（Windows 用 `gradlew.bat runData`）。
- 生成结果在 `src/generated/resources`：模型进 `assets/`，配方/战利品/标签进 `data/`，和手写路径一一对应。
- 手写与 Datagen **二选一**：同名文件会冲突，建议全部改用生成，手写只保留贴图、`neoforge.mods.toml` 这类非数据文件。
