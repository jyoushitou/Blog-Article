## 使用boost/json序列化

> 和字典类似

```cpp
//让ArticleMeta变为Json对象
json::object to_json_object(const ArticleMeta& a) {
    json::array tags;
    //tags的数组
    for (const auto& t : a.tags) {
        tags.emplace_back(t);
    }

    json::object o;
    o["slug"]    = a.slug;
    o["title"]   = a.title;
    o["date"]    = a.date;
    o["tags"]    = std::move(tags);
    o["summary"] = a.summary;
    return o;
}

//序列化
std::string build_article_list(const std::vector<ArticleMeta>& articles) {
    json::array arr;
    for (const auto& a : articles) {
        arr.emplace_back(to_json_object(a));   // 注意用 emplace_back
    }
    return json::serialize(arr);               // 顶层就是 [ ... ]
}
```

- 这样就获得了一个封装的json对象后序列化成string的
- 并且tags是一个数组！

## RapidJSON

> 性能最好

```cpp
#include "rapidjson/document.h"
#include "rapidjson/writer.h"
#include "rapidjson/stringbuffer.h"

using namespace rapidjson;

// 把 ArticleMeta 写进已有的 writer
template <class Writer>
void write_meta(Writer& w, const ArticleMeta& a) {
    w.StartObject();
    w.Key("slug");    w.String(a.slug.c_str());
    w.Key("title");   w.String(a.title.c_str());
    w.Key("date");    w.String(a.date.c_str());
    w.Key("summary"); w.String(a.summary.c_str());

    w.Key("tags");
    w.StartArray();
    for (const auto& t : a.tags) w.String(t.c_str());
    w.EndArray();
    w.EndObject();
}

std::string build_article_list(const std::vector<ArticleMeta>& articles) {
    StringBuffer sb;
    Writer<StringBuffer> w(sb);
    w.StartArray();
    for (const auto& a : articles) write_meta(w, a);
    w.EndArray();
    return sb.GetString();
}

std::string build_article_detail(const ArticleDetail& d) {
    StringBuffer sb;
    Writer<StringBuffer> w(sb);
    w.StartObject();
    w.Key("slug");    w.String(d.meta.slug.c_str());
    w.Key("title");   w.String(d.meta.title.c_str());
    w.Key("date");    w.String(d.meta.date.c_str());
    w.Key("summary"); w.String(d.meta.summary.c_str());
    w.Key("tags");
    w.StartArray();
    for (const auto& t : d.meta.tags) w.String(t.c_str());
    w.EndArray();
    w.Key("content"); w.String(d.content.c_str());
    w.EndObject();
    return sb.GetString();
}
```

- 写入需要对应的start函数和end函数
- 使用的是缓冲区直接写入，比如：**w.Key("slug"); w.String(a.slug.c_str());**时就是先写入**slug:**再写入内容**对应的内容**，对应的库会自动添加json符号

## 直接拼！

```cpp
#include <string>
#include <sstream>

// 把 UTF-8 字符串转义成合法 JSON 字符串内容（不含首尾引号）
std::string escape(const std::string& s) {
    std::string out;
    out.reserve(s.size() + 8);
    for (unsigned char c : s) {
        switch (c) {
            case '"':  out += "\\\""; break;
            case '\\': out += "\\\\"; break;
            case '\n': out += "\\n";  break;
            case '\r': out += "\\r";  break;
            case '\t': out += "\\t";  break;
            default:
                if (c < 0x20) {                 // 控制字符 -> \u00XX
                    char buf[8];
                    std::snprintf(buf, sizeof buf, "\\u%04x", c);
                    out += buf;
                } else {
                    out += static_cast<char>(c); // >=0x80 直接原样输出(UTF-8)
                }
        }
    }
    return out;
}

std::string build_article_list(const std::vector<ArticleMeta>& articles) {
    std::ostringstream os;
    os << '[';
    for (size_t i = 0; i < articles.size(); ++i) {
        const auto& a = articles[i];
        if (i) os << ',';
        os << "{\"slug\":\""    << escape(a.slug)
           << "\",\"title\":\"" << escape(a.title)
           << "\",\"date\":\""  << escape(a.date)
           << "\",\"summary\":\"" << escape(a.summary) << "\",\"tags\":[";
        for (size_t j = 0; j < a.tags.size(); ++j) {
            if (j) os << ',';
            os << '"' << escape(a.tags[j]) << '"';
        }
        os << "]}";
    }
    os << ']';
    return os.str();
}

std::string build_article_detail(const ArticleDetail& d) {
    std::ostringstream os;
    os << "{\"slug\":\""    << escape(d.meta.slug)
       << "\",\"title\":\"" << escape(d.meta.title)
       << "\",\"date\":\""  << escape(d.meta.date)
       << "\",\"summary\":\"" << escape(d.meta.summary)
       << "\",\"tags\":[";
    for (size_t j = 0; j < d.meta.tags.size(); ++j) {
        if (j) os << ',';
        os << '"' << escape(d.meta.tags[j]) << '"';
    }
    os << "],\"content\":\"" << escape(d.content) << "\"}";
    return os.str();
}
```

> 适合固定的字段，且不导入额外库，应该适合无网的环境不能下库的情况

# 计算机组成原理

# 总线

> 总线是连接多个部件的信息传输线，是各部件共享的传输介质。
> 同一时刻只允许一个部件（或一对部件）向总线发送信息，但允许多个部件同时接收（通过总线仲裁 + 分时复用实现）。

## 结构

### 单总线

> 所有部件（CPU、主存、I/O）都挂在一组总线上，同一组线既传地址、又传数据、还传控制。

```text
        ┌─────┐   ┌─────┐   ┌─────┐   ┌─────┐
        │ CPU │   │主存 │   │ I/O │   │ I/O │
        └──┬──┘   └──┬──┘   └──┬──┘   └──┬──┘
           │         │         │         │
   ────────┴─────────┴─────────┴─────────┴────────
   ═══════════════ 单 一 系 统 总 线 ═══════════════
      (数据总线 / 地址总线 / 控制总线 复用)
```

- 结构简单、成本低、易于扩展
- 缺点：所有部件争用一条总线，**同一时刻只能有一对部件通信**，带宽瓶颈
- 多用于早期机器和简单的嵌入式系统

---

### 双总线

> 把「CPU—主存」的高速通道与「I/O」通道分开，缓解单总线拥挤。

```text
  ┌─────┐        存储总线（高速）
  │ CPU │════════════════════════════┌─────┐
  └──┬──┘                            │主存 │
     │                               └─────┘
     │ I/O 总线（低速）
  ───┴───────────────┬───────────────┬─────────
                     │               │
                  ┌──┴──┐         ┌──┴──┐
                  │ I/O │         │ I/O │
                  └─────┘         └─────┘
```

- 典型形式：CPU 与主存之间单独一条高速总线（存储总线）
- CPU 通过 I/O 总线连接各外设；两条总线可并行工作
- 优点：主存访问不受 I/O 影响，提升整体效率
- 缺点：结构变复杂，CPU 仍可能成为瓶颈

---

### 三总线

> 在主存总线、I/O 总线之外，再引入 DMA 总线，让外设与主存直接交换数据。

```text
  ┌─────┐   主存总线   ┌─────┐
  │ CPU │═════════════│主存 │
  └──┬──┘             └──┬──┘
     │                   │  DMA 总线
     │ I/O 总线          │
  ───┴──────────┐    ┌───┴───┐        ┌───────┐
                └────┤  DMA  ├────────┤ 外设  │
                     └───────┘        └───────┘
                     ┌─────┐  ┌─────┐
                     │ I/O │  │ I/O │
                     └─────┘  └─────┘
```

- 三条总线：**主存总线**、**I/O 总线**、**DMA 总线**
- CPU 与主存走主存总线；外设与主存走 DMA 总线，实现成块数据的高速搬运
- 优点：DMA 期间 CPU 可继续访存/运算，进一步解放 CPU
- 缺点：硬件成本最高，结构最复杂

### 四总线

> 在三总线基础上再引入一条高速扩展总线（如 PCIe），让显卡、网卡等高速板卡与低速 I/O 分开挂在不同的总线上。

```text
  ┌─────┐   主存总线   ┌─────┐
  │ CPU │═════════════│主存 │
  └──┬──┘             └──┬──┘
     │                   │  DMA 总线
     │ I/O 总线          │
  ───┴───────┐     ┌─────┴─────┐
             │     │    DMA    │
             │     └─────┬─────┘
             │           │
        ┌────┴───────────┴────┐
        │   扩展总线 (PCIe)   │  ← 第四条总线
        └──┬───────┬──────┬───┘
           │       │      │
        ┌──┴─┐  ┌──┴─┐  ┌─┴──┐
        │显卡│  │网卡│  │外设│
        └────┘  └────┘  └────┘
```

- 四条总线：**主存总线**、**I/O 总线**、**DMA 总线**、**扩展总线（PCIe）**
- 高速设备（显卡、网卡、SSD）走扩展总线，低速设备（键盘、串口）走 I/O 总线，避免相互拖累
- 优点：总线层次分明，各类设备各得其所，整体吞吐最高
- 缺点：桥接与总线仲裁逻辑最复杂，硬件成本也最高

### VL_BUS

> VESA Local Bus（VLB）是一种局部总线，把高速外设直接挂到 CPU 的局部总线上（而非桥接到慢速的 I/O 总线），从而绕开系统总线瓶颈，让显卡、硬盘控制器等设备与 CPU 高速通信。

```text
  ┌─────┐      CPU 局部总线（地址/数据/控制）      ┌─────┐
  │ CPU │══════════════════════════════════════════│主存 │
  └──┬──┘                                          └─────┘
     │
     │   VESA 局部总线 VLB（32 位 / 64 位）
  ───┴──────┬──────────────┬──────────────┬───────────
            │              │              │
        ┌───┴───┐      ┌───┴───┐      ┌───┴───┐
        │ 显卡  │      │硬盘   │      │ 网卡  │
        │ (VLB) │      │控制器 │      │ (VLB) │
        └───────┘      └───────┘      └───────┘
```

- 本质：把 CPU 的局部总线直接引出，高速设备（显卡、磁盘控制器）经 VLB 槽直连 CPU，不再挤 I/O 总线
- 特点：传输速率接近 CPU 主频，明显快于当时的 ISA / PCI 之外的低速总线
- 缺点：与 CPU 时序强耦合，**频率受 CPU 限制**、扩展槽数量少（一般 2～3 个）、对 CPU 类型依赖强、缺乏统一仲裁
- 结局：被即插即用、独立于 CPU 的 **PCI 总线**取代

### PCI

> PCI（Peripheral Component Interconnect）是一种与 CPU 无关、即插即用的并行局部总线，通过 **桥（Host Bridge / PCI Bridge）** 把高速外设与 CPU、主存连接起来，彻底摆脱了 VLB 对 CPU 时序的强耦合。

```text
  ┌─────┐   主存总线   ┌─────┐
  │ CPU │═════════════│主存 │
  └──┬──┘             └──┬──┘
     │                   │
     │  CPU 局部总线     │
  ───┴────────┬──────────┴───┐
              │              │
        ┌─────┴─────┐        │  ← Host Bridge（北桥）
        │  Host     │        │     连接 CPU / 主存 / PCI
        │  Bridge   │────────┘
        └─────┬─────┘
              │
   ═══════════╧═══════════════════════════════════
   ║      PCI 总线（32/64 位，33/66 MHz）        ║
   ═══╤═══════════╤═══════════╤═══════════╤═══════
      │           │           │           │
  ┌───┴───┐   ┌───┴───┐   ┌───┴───┐   ┌───┴────┐
  │ 显卡  │   │ 网卡  │   │ 声卡  │   │PCI 桥  │
  │ (PCI) │   │ (PCI) │   │ (PCI) │   │(南桥)  │
  └───────┘   └───────┘   └───────┘   └───┬────┘
                                          │
                                     ISA / IDE / USB
                                     （低速设备）
```

- 特点：**独立于 CPU**，不与 CPU 时钟强耦合，插槽数量多（一般 3～5 个），支持 32/64 位、33/66 MHz
- 即插即用：由总线仲裁器统一分配资源、动态分配中断/地址，无需手动跳线
- 结构：通过 **Host Bridge（北桥）** 连接 CPU 与主存，通过 **PCI-to-ISA 桥（南桥）** 挂接低速设备，形成层次化总线
- 优点：不依赖具体 CPU 型号、通用性强、支持突发传输（Burst），是 VLB 的正式替代者
- 缺点：并行共享总线，**同一时刻仍只能有一对设备通信**，带宽随设备增多被瓜分；后被点到点的 **PCIe** 取代

### 多层PCI

> 单条 PCI 总线仍是共享介质，挂载设备一多带宽就被瓜分。多层 PCI 通过 **PCI-to-PCI 桥** 把原来的一条 PCI 总线拆成多条（树状层次），每一段都是独立的 PCI 总线段，桥负责在上下游之间转发事务，从而把流量分散到多段总线上。

```text
  ┌─────┐   主存总线   ┌─────┐
  │ CPU │═════════════│主存 │
  └──┬──┘             └──┬──┘
     │                   │
     │  CPU 局部总线     │
  ───┴────────┬──────────┴───┐
              │              │
        ┌─────┴─────┐        │  ← Host Bridge（北桥）
        │  Host     │        │     连接 CPU / 主存 / PCI(总线0)
        │  Bridge   │────────┘
        └─────┬─────┘
              │
   ═══════════╧═══════════════════════════════════
   ║      PCI 总线 0（主 PCI 段）                ║
   ═══╤═══════════╤═══════════╤════════════╤══════
      │           │           │            │
  ┌───┴───┐   ┌───┴───┐   ┌───┴───┐   ┌────┴────┐
  │ 显卡  │   │ 网卡  │   │ 声卡  │   │ PCI-PCI │
  │ (PCI) │   │ (PCI) │   │ (PCI) │   │  Bridge │
  └───────┘   └───────┘   └───────┘   └────┬────┘
                                            │
   ═════════════════════════════════════════╧═════
   ║      PCI 总线 1（次级 PCI 段）              ║
   ═══╤═══════════╤═══════════╤═══════════╤═══════
      │           │           │           │
  ┌───┴───┐   ┌───┴───┐   ┌───┴───┐   ┌───┴────┐
  │ SCSI  │   │ 网卡  │   │ 声卡  │   │PCI-ISA │
  │控制器 │   │ (PCI) │   │ (PCI) │   │ 桥(南桥)│
  └───────┘   └───────┘   └───────┘   └───┬────┘
                                          │
                                     ISA / IDE / USB
                                     （低速设备）
```

- 结构：**Host Bridge（北桥）** 引出主 PCI 段（**总线 0**），再由 **PCI-to-PCI 桥** 向下挂出次级 PCI 段（**总线 1、2…**），整体是一棵 **PCI 总线树**
- 关键点：每段 PCI 总线**各自仲裁、各自带宽**，设备被分散到不同段上，避免都挤在同一条总线上争用
- 桥的作用：**事务转发 + 总线号编址**（上游/下游地址窗口），对上层软件仍表现为统一的一棵 PCI 配置空间树
- 优点：可挂设备数量更多、流量互相隔离、不同段可用不同频率/位宽，扩展性好
- 缺点：跨段访问必须经桥转发，**增加延迟**；桥的配置、总线号分配与仲裁逻辑更复杂，硬件成本上升
- 演进：多层 PCI 之上再引出 **AGP / PCIe** 等专用高速链路，最终由点到点的 **PCIe** 全面取代并行 PCI

## 控制

### 解决总线判优控制

#### 概念

- 根据是否能提出总线请求
  - 主设备：对总线有控制权
  - 从设备：只能响应主设备发来的总线命令
- 判优控制
  - 集中式
    - 链式查询
    - 计数器定时查询
    - 独立请求方式
  - 分布式

#### 链式查询

- BS:总线忙
- BR:总线请求
- BG:总线同意
  > 优点：简单！可靠性设计容易实现

#### 计数器定时查询

- BS:总线忙
- BR:总线请求

##### 三条线

- 数据线
- 地址线
- 设备地址
  > 为了查找是否是总线发出的请求

#### 优点

- 优先级比较灵活

#### 独立请求方式

- 为每个I/O设备接口都加入BR和BG与总线控制部件连接
