# c++

# 线程库

C++ 线程库从 C++11 开始引入，主要头文件有 `<thread>`、`<mutex>`、`<condition_variable>`、`<atomic>`、`<future>`、`<shared_mutex>`，C++20 又新增了 `<semaphore>`、`<latch>`、`<barrier>` 以及 `std::jthread`。

## std::thread

### 基本用法

`std::thread` 表示一个可执行线程，构造时传入可调用对象（函数、lambda、函数对象）及其参数。

```cpp
#include <thread>
#include <iostream>

void hello(int id) {
    std::cout << "thread " << id << '\n';
}

int main() {
    std::thread t(hello, 1);   // 启动线程
    t.join();                  // 等待线程结束
}
```

### join 与 detach

- `join()`：阻塞当前线程直到目标线程执行完毕，之后该 `thread` 对象不再关联线程。
- `detach()`：把线程与 `thread` 对象分离，交给运行时管理，之后不能再 `join`。
- 二者**必须调用其一**，否则 `std::thread` 析构时若仍 `joinable()` 会直接 `std::terminate`。

```cpp
std::thread t([]{ /* ... */ });
if (t.joinable()) t.join();  // 或 t.detach();
```

### 传参注意

参数默认**按值拷贝**到线程内部存储。要传引用必须用 `std::ref`，且要保证被引用对象的生命周期长于线程。

```cpp
void add(int& x) { x += 1; }

int n = 0;
std::thread t(add, std::ref(n));  // 必须 std::ref，否则拷贝一份
t.join();
```

### 其它成员

| 成员函数                         | 说明                       |
| -------------------------------- | -------------------------- |
| `joinable()`                     | 是否关联着一个活动线程     |
| `get_id()`                       | 返回 `std::thread::id`     |
| `hardware_concurrency()`（静态） | 建议的并发线程数，可能为 0 |

## std::jthread（C++20）

`std::jthread` 是 `std::thread` 的改进版，析构时**自动 join**，并且支持**协作式取消**（`std::stop_token`）。

```cpp
#include <thread>

int main() {
    std::jthread jt([](std::stop_token st) {
        while (!st.stop_requested()) {
            // 循环工作
        }
    });
    // 离开作用域时自动请求停止并 join
}
```

| 对比     | `std::thread`        | `std::jthread`                |
| -------- | -------------------- | ----------------------------- |
| 析构行为 | 未 join 则 terminate | 自动请求停止并 join           |
| 取消支持 | 无                   | `stop_token` / `request_stop` |

## 互斥量 std::mutex

多个线程访问共享数据时需要互斥保护，否则会产生**数据竞争（data race）**，属于未定义行为。

### 常用互斥类型

| 类型                   | 头文件           | 说明                              |
| ---------------------- | ---------------- | --------------------------------- |
| `std::mutex`           | `<mutex>`        | 最基本的互斥量                    |
| `std::recursive_mutex` | `<mutex>`        | 同一线程可重复加锁                |
| `std::timed_mutex`     | `<mutex>`        | 支持带超时的 `try_lock_for/until` |
| `std::shared_mutex`    | `<shared_mutex>` | 读写锁，多读单写（C++17）         |

### lock / unlock 直接用法

```cpp
std::mutex mtx;
int counter = 0;

void work() {
    mtx.lock();
    ++counter;      // 临界区
    mtx.unlock();   // 若中途抛异常则不会解锁，不推荐
}
```

## RAII 锁管理器

手动 `lock/unlock` 容易忘记解锁，标准库提供了 RAII 封装。

### std::lock_guard

最简单的 RAII 锁，构造即加锁，析构即解锁，**不可手动解锁、不可移动**。

```cpp
std::mutex mtx;
void safe() {
    std::lock_guard<std::mutex> lk(mtx);
    // 临界区，离开作用域自动解锁
}
```

### std::unique_lock

更灵活，支持延迟加锁、手动解锁、移动，配合条件变量使用，代价是略高一点的开销。

```cpp
std::unique_lock<std::mutex> lk(mtx, std::defer_lock); // 先不锁
lk.lock();          // 手动加锁
// ...
lk.unlock();        // 手动解锁
```

### std::scoped_lock（C++17）

一次锁定**多个**互斥量，内部用死锁避免算法，是推荐的多锁用法。

```cpp
std::mutex m1, m2;
void transfer() {
    std::scoped_lock lock(m1, m2);  // 同时锁住，避免死锁
    // ...
}
```

### 三种锁对比

| 类型          | 能否手动解锁 | 能否移动 | 适用场景           |
| ------------- | ------------ | -------- | ------------------ |
| `lock_guard`  | 否           | 否       | 简单作用域加锁     |
| `unique_lock` | 是           | 是       | 条件变量、灵活加锁 |
| `scoped_lock` | 否           | 否       | 同时锁多个互斥量   |

## 条件变量 std::condition_variable

用于线程间等待 / 通知，常配合 `std::unique_lock` 使用，典型是生产者-消费者模型。

```cpp
#include <condition_variable>
#include <mutex>
#include <queue>

std::mutex mtx;
std::condition_variable cv;
std::queue<int> q;

void producer() {
    {
        std::lock_guard<std::mutex> lk(mtx);
        q.push(42);
    }
    cv.notify_one();   // 通知一个等待线程
}

void consumer() {
    std::unique_lock<std::mutex> lk(mtx);
    cv.wait(lk, []{ return !q.empty(); }); // 带谓词，防虚假唤醒
    int v = q.front();
    q.pop();
}
```

### 要点

- 等待必须用 `wait(lk, pred)` 这种**带谓词**的写法，防止**虚假唤醒（spurious wakeup）**。
- 修改共享状态后再 `notify`，也可以在解锁后再通知，减少等待线程立刻阻塞。
- `notify_one` 唤醒一个，`notify_all` 唤醒全部。

| 成员             | 说明                                 |
| ---------------- | ------------------------------------ |
| `wait(lk)`       | 阻塞直到被唤醒（需自己处理虚假唤醒） |
| `wait(lk, pred)` | 等价于 while(!pred()) wait(lk)       |
| `wait_for/until` | 带超时的等待                         |
| `notify_one/all` | 唤醒一个 / 全部等待线程              |

## 原子操作 std::atomic

对简单共享变量，用原子类型可以避免加锁，无锁且高效。

```cpp
#include <atomic>

std::atomic<int> cnt{0};

void inc() {
    cnt.fetch_add(1, std::memory_order_relaxed);
    // 或 cnt++; 默认 memory_order_seq_cst
}
```

### 内存序 memory_order

| 内存序                         | 说明                              |
| ------------------------------ | --------------------------------- |
| `memory_order_relaxed`         | 只保证原子性，不保证顺序          |
| `memory_order_acquire/release` | 获取 / 释放语义，常用于标志位同步 |
| `memory_order_seq_cst`         | 默认，最强一致性，开销最大        |

- `std::atomic_flag` 是唯一保证 lock-free 的原子类型。
- `std::atomic<T>` 对自定义类型不一定无锁，可用 `is_lock_free()` 查询。
- `std::atomic<std::shared_ptr<T>>` 是 C++20 新增，可原子操作智能指针。

## 异步任务 std::async / std::future

`std::async` 把任务丢给线程执行，返回 `std::future` 用来取结果。

```cpp
#include <future>

int compute() { return 42; }

int main() {
    std::future<int> f = std::async(std::launch::async, compute);
    int r = f.get();   // 阻塞直到结果就绪
}
```

### 启动策略

| 策略                    | 说明                             |
| ----------------------- | -------------------------------- |
| `std::launch::async`    | 立刻新开线程执行                 |
| `std::launch::deferred` | 延迟到 `get()`/`wait()` 时才执行 |
| 默认（不指定）          | 二者皆可，由实现决定             |

### future / promise / packaged_task

| 工具                 | 说明                                     |
| -------------------- | ---------------------------------------- |
| `std::future`        | 读取异步结果，`get()` 只能调用一次       |
| `std::shared_future` | 可多次读取、可拷贝                       |
| `std::promise`       | 手动设置结果，与 `future` 配对           |
| `std::packaged_task` | 包装可调用对象，可取出 future 后延迟执行 |

```cpp
std::promise<int> p;
std::future<int> f = p.get_future();
std::thread t([&p]{ p.set_value(7); });
int v = f.get();
t.join();
```

## 一次性初始化 call_once / once_flag

保证某段代码在多线程下只执行一次，替代手写双重检查锁。

```cpp
#include <mutex>

std::once_flag flag;
void init() {
    std::call_once(flag, []{
        // 只会执行一次，线程安全
    });
}
```

## C++20 同步原语

| 类型                      | 头文件        | 说明                      |
| ------------------------- | ------------- | ------------------------- |
| `std::counting_semaphore` | `<semaphore>` | 计数信号量                |
| `std::binary_semaphore`   | `<semaphore>` | 计数为 1 的信号量         |
| `std::latch`              | `<latch>`     | 一次性倒计数，到 0 后放行 |
| `std::barrier`            | `<barrier>`   | 可复用的屏障，多阶段同步  |

```cpp
#include <latch>

std::latch done(3);
// 3 个线程各自完成后 done.count_down();
done.wait();  // 主线程等待全部完成
```

## 常见陷阱

- **忘记 join/detach**：`std::thread` 析构时 `terminate`。
- **数据竞争**：共享数据未加锁，未定义行为。
- **死锁**：多把锁加锁顺序不一致；应使用 `std::scoped_lock` 或统一加锁顺序。
- **虚假唤醒**：`condition_variable` 未用谓词判断。
- **传引用未用 std::ref**：参数被拷贝，修改无效。
- **detach 后的悬垂引用**：分离线程仍访问已销毁的对象。
