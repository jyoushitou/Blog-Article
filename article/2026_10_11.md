# c++

# 原子变量

## 为什么需要原子变量

多线程同时读写同一个变量会产生**数据竞争（data race）**，导致未定义行为。普通加锁（`std::mutex`）虽然能解决，但有开销，且容易死锁。

`std::atomic` 提供了一种**无锁（lock-free）**的、由编译器和 CPU 保证原子性的方式，用于对单个变量做并发读写。

## 基本用法

```cpp
#include <atomic>

std::atomic<int> counter{0};

void worker() {
    for (int i = 0; i < 1000; ++i)
        counter.fetch_add(1, std::memory_order_relaxed); // 原子自增
}
```

`std::atomic<T>` 支持的类型：整型、指针、以及满足 trivially copyable 的自定义类型（如 `std::atomic<int>`、`std::atomic<bool>`、`std::atomic<void*>` 等）。

## 常用成员函数

| 操作 | 说明 |
| --- | --- |
| `load()` | 原子读取 |
| `store(v)` | 原子写入 |
| `exchange(v)` | 写入并返回旧值 |
| `fetch_add(v)` / `fetch_sub(v)` | 原子加减，返回旧值 |
| `fetch_and/or/xor` | 位运算 |
| `compare_exchange_weak/strong` | CAS，实现无锁数据结构的基础 |

另外还重载了 `++`、`--`、`+=`、`-=` 等运算符（读-改-写操作是原子的）。

```cpp
std::atomic<bool> flag{false};

// 简易自旋锁
void lock() { while (flag.exchange(true, std::memory_order_acquire)) {} }
void unlock() { flag.store(false, std::memory_order_release); }
```

## 内存序（memory_order）

编译器和 CPU 会为了性能对指令**重排**。内存序用来控制可见性和重排约束，从弱到强大致为：

- `memory_order_relaxed`：只保证原子性，不保证顺序，性能最高。
- `memory_order_acquire` / `memory_order_release`：用于同步，配对使用（读用 acquire，写用 release）。
- `memory_order_acq_rel`：读-改-写操作同时具有 acquire 和 release 语义。
- `memory_order_seq_cst`：默认值，最强，全局顺序一致，最安全但最慢。

**建议**：除非有明确性能需求，默认使用 `seq_cst`。

## 注意点

1. 单独的 `atomic` 操作是原子的，但**多个操作组合起来不是**，需要 CAS 或互斥量。
2. `T` 只是简单类型时 `is_lock_free()` 通常为真，但并非所有类型都无锁。
3. 用 `std::atomic_flag` 可以保证一定无锁，可用作 `atomic<bool>` 的替代。
4. C++20 起 `std::atomic<T>` 支持 `wait()` / `notify_one()` / `notify_all()`，可替代条件变量做轻量同步。

```cpp
std::atomic<int> v{0};

// 线程 A
v.store(42, std::memory_order_release);

// 线程 B
int x = v.load(std::memory_order_acquire); // 若看到 42，则 A 之前的写入都可见
```
