## self指针(继承自std::enable_shared_from_this < T > )

### 一、为什么需要 self 指针

在异步编程中（Boost.Asio），回调函数通常在对象已经析构之后才被执行，导致访问已释放的内存（悬空指针）。

```cpp
void Session::start()
{
    // 错误做法：只捕获 this
    // 如果 Session 在异步读完成前被销毁，回调里访问 this 就是 UAF
    _socket.async_read_some(boost::asio::buffer(_data, max_length),
        std::bind(&Session::handle_read, this,
            std::placeholders::_1, std::placeholders::_2));
}
```

要解决这个问题，就需要在回调期间「保活」——让对象在异步操作完成前不被销毁。做法是把一个指向自身的 `shared_ptr` 作为参数传进回调，使引用计数 +1，等回调执行完再 -1。

问题是：在 `Session` 类内部，我们只有 `this` 裸指针，怎么拿到管理自己的那个 `shared_ptr`？

答案是继承 `std::enable_shared_from_this<T>`，通过 `shared_from_this()` 获得。

```cpp
class Session : public std::enable_shared_from_this<Session>
{
public:
    void start()
    {
        // 保活：引用计数 +1，回调执行完自动释放
        auto self = shared_from_this();
        _socket.async_read_some(boost::asio::buffer(_data, max_length),
            [this, self](const boost_error_code& ec, size_t bytes)
            {
                handle_read(ec, bytes);
            });
    }
private:
    tcp::socket _socket;
    char _data[1024];
};
```

### 二、原理

`enable_shared_from_this<T>` 内部有一个 `std::weak_ptr<T>` 成员（`weak_this`）。

- 当对象被 `shared_ptr` 接管时（`make_shared` 或 `shared_ptr` 构造），`shared_ptr` 的构造函数会检测到基类，把 `weak_this` 指向这个控制块。
- 调用 `shared_from_this()` 时，就是 `weak_this.lock()`，由此得到一个指向自身的 `shared_ptr`，同时和原来的 `shared_ptr` 共享同一个引用计数。

所以 `shared_from_this()` 返回的指针**不是新建的控制块**，不会导致重复析构。

### 三、三个必须注意的坑

1. **对象必须由 `shared_ptr` 管理**：如果对象是栈上创建的，或者由裸 `new` 创建未交给 `shared_ptr`，`weak_this` 是空的，调用 `shared_from_this()` 会抛 `std::bad_weak_ptr`。

```cpp
Session s;              // 栈上对象
s.shared_from_this();   // 抛 std::bad_weak_ptr

auto sp = std::make_shared<Session>();  // 正确
sp->shared_from_this();                 // OK
```

2. **不能在构造函数里调用**：构造函数执行时，`shared_ptr` 还没接管对象，`weak_this` 尚未设置。

```cpp
Session::Session()
{
    auto self = shared_from_this(); // 错误：bad_weak_ptr
}
```

3. **不要在析构函数里调用**：析构时引用计数已归零，`weak_this.lock()` 返回空。

### 四、在继承链中的向下转换

当类存在多级继承时，`enable_shared_from_this<T>` 只定义在某一层，子类的 `shared_from_this()` 需要向下转型（downcast），因为 `shared_ptr` 不支持隐式向下转型。

假设继承链为 `HttpSession → Session → Connection`，且 `Connection` 才是 `enable_shared_from_this<Connection>` 的基类：

```cpp
// Connection 层：真正的 enable_shared_from_this
class Connection : public std::enable_shared_from_this<Connection>
{
public:
    // 返回 shared_ptr<Connection>
};

// Session 层：向下转型
class Session : public Connection
{
public:
    std::shared_ptr<Session> shared_from_this()
    {
        return std::static_pointer_cast<Session>(Connection::shared_from_this());
    }
};

// HttpSession 层：继续向下转型
class HttpSession : public Session
{
public:
    std::shared_ptr<HttpSession> shared_from_this()
    {
        return std::static_pointer_cast<HttpSession>(Session::shared_from_this());
    }
};
```

**为什么用 `static_pointer_cast` 是安全的**：它不改变引用计数，只改变指针的静态类型；前提是所有对象都是通过 `make_shared<HttpSession>` 创建的，控制块类型与实际派生类型一致。

**函数遮蔽**：`HttpSession::shared_from_this()` 隐藏了基类的同名函数。由于这不是虚函数，通过 `Session*` 调用会得到 `shared_ptr<Session>`，通过 `HttpSession*` 调用才得到 `shared_ptr<HttpSession>`。
