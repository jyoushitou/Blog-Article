## 一、using 的四种主要用途

C++ 中的 `using` 关键字在不同语境下含义差别很大，可归纳为：

| 用途                                               | 语法                                                                  | 出现位置                           |
| -------------------------------------------------- | --------------------------------------------------------------------- | ---------------------------------- |
| using 声明（引入单个名字）                         | `using std::cout;`                                                    | 命名空间作用域、块作用域、类作用域 |
| using 指令（引入整个命名空间）                     | `using namespace std;`                                                | 命名空间作用域、块作用域           |
| 类型别名 / 别名模板                                | `using Int = int;`<br>`template<class T> using Vec = std::vector<T>;` | 命名空间、类、块作用域             |
| 类成员引入（改变可见性/继承构造函数/`using enum`） | `using Base::foo;`<br>`using Base::Base;`<br>`using enum Color;`      | 类作用域、块作用域                 |

## 二、using 声明（using-declaration）

把某个命名空间中的**一个名字**引入当前作用域，之后可直接使用该短名。

```cpp
#include <iostream>
#include <vector>

void f() {
    using std::cout;          // 只引入 cout
    using std::vector;        // 只引入 vector
    cout << "hello\n";
    vector<int> v{1, 2, 3};
}
```

要点：

1. 作用域局限于所在的块/命名空间，出了作用域即失效。
2. 引入的是**名字**而非“文本替换”，因此遵循重载、模板、ADL 等正常规则。
3. 同一个作用域内重复 using 声明同一个名字是合法的（C++17 前某些情况会有警告）。
4. `using ::name;` 可显式从全局命名空间引入。

### 用于“恢复被隐藏的名字”

派生类定义同名函数会**隐藏**基类的所有同名重载（名字隐藏，name hiding），用 using 声明可以把基类重载重新引入同一个重载集：

```cpp
struct Base {
    void foo(int);
    void foo(double);
};

struct Derived : Base {
    void foo(const char*);      // 隐藏了 Base::foo(int/double)
};

struct Derived2 : Base {
    using Base::foo;            // 把 Base 的两个重载拉进来
    void foo(const char*);      // 与它们共同构成重载集
};

Derived  d;  d.foo(1);      // 错误：Base::foo 被隐藏（除非经 d.Base::foo(1)）
Derived2 d2; d2.foo(1);     // OK，调用 Base::foo(int)
```

### 用于改变成员访问权限

核心规则：**被 using 声明引入的名字，其访问级别由 using 声明所在的访问区决定**，而不是由它在基类中的级别决定。因此既能提升，也能**降级**，函数与数据成员（含静态成员）都适用：

```cpp
class Base {
protected:
    void helper();
public:
    void api();
};

class Widget : private Base {
public:
    using Base::api;      // 私有继承来的 public 成员重新暴露为 public
    using Base::helper;   // protected → public
};
```

> 关键：using 声明只是**把名字引进来**，访问级别看它写在哪个访问区；它不改变基类本身的访问级别，也不改变虚函数的虚分派行为。

#### 1. 提升：private/protected 继承 → public（“选择性暴露”）

私有继承是“实现继承”，通过 using 把需要的成员逐个放出来，是很常见的 idiom（比改成 public 继承更收敛接口）。注意 `api` 在基类本就是 public，但因私有继承整体被降为 private，必须用 using 重新“放出来”——上面的 `Widget` 就是此例。

#### 2. 降级：public 继承 → private / protected（“选择性隐藏”）

反过来完全合法，且**最常被忽略**——把 public 继承来的成员在派生类里收窄成 private，用 `private:` 区写 using 即可：

```cpp
class Base {
public:
    void f();
    int  g(int);
    static int counter;      // 静态数据成员
};

class Derived : public Base {
private:
    using Base::g;           // g 在 Derived 里变成 private
    using Base::counter;     // 静态数据成员也能引入并降级
    // f 不写 using：仍保持 public
};
```

**重要限制**：这种“降级”只对**通过 Derived 名字**发起的访问生效。访问控制按**静态类型**检查，所以仍可绕过：

```cpp
Derived d;
d.g(1);                      // 错误：g 在 Derived 中是 private
d.Base::g(1);                // 合法！限定名走 Base，Base::g 是 public
static_cast<Base&>(d).g(1);  // 合法！按 Base 的访问级别检查
```

因此**降级是“接口设计意图”的表达，不是安全边界**。想真正禁止，只能私有继承或改写封装。

#### 3. 函数 / 静态数据成员可以，非静态数据成员不行

这是最容易踩的一条：using 声明**不能命名非静态数据成员**。

```cpp
class Holder {
public:
    int   x;                 // 非静态数据成员
    static int s;            // 静态数据成员
    void  f();               // 成员函数
};

class Derived : public Holder {
private:
    using Holder::f;         // ✅ 成员函数
    using Holder::s;         // ✅ 静态数据成员
    // using Holder::x;      // ❌ 编译错误：using 声明不能引入非静态数据成员
};
```

C++ 标准规定 using 声明不得命名非静态数据成员，编译器会直接报错（GCC/Clang/MSVC 均拒绝）。想对**非静态数据成员**改访问级别，只能换手段：

```cpp
// 手段 A：私有继承 + 自己写访问函数（真正隔离）
class Derived2 : private Holder {
public:
    int&  x()       { return Holder::x; }
    int   x() const { return Holder::x; }
};

// 手段 B：组合（优先推荐，C++ 惯例“组合优于继承”）
class Derived3 {
public:
    int& x() { return impl_.x; }
private:
    Holder impl_;
};
```

同理，using 声明也不能命名**析构函数**，不能引入**模板参数**。

#### 4. 继承构造函数也能设访问级别

```cpp
class Token {
private:
    using Base::Base;        // 继承来的构造全部变成 private
public:
    static Token create(int id) { return Token{id}; }  // 唯一入口
};
```

这样 `Token t{42};` 在外部不可用，只能走工厂函数（配合 `std::make_unique` 的 `private` 构造函数 idiom 同源）。

#### 5. 其他细则

1. **与派生类自有声明冲突会报错**：派生类已有 `void f(int)`，再 `using Base::f;`（且 `Base::f(int)` 存在）→ 同签名冲突，编译失败；不同签名才构成合法重载集。
2. **不影响虚函数分派**：using 只影响名字可见性与访问检查，`override`/虚表行为不变。
3. **`using` 声明引入后仍是“同一个实体”**，不是新函数；取地址、`decltype`、模板实参推导都指向基类那个。
4. **访问检查发生在编译期**：using 降级后，模板里通过 `derived.template f<T>()` 之类调用同样会被拦。
5. **`using` 不能为成员改名**，也不能在 using 里加 `const`/`noexcept` 修饰。

## 三、using 指令（using-directive）

```cpp
using namespace std;
```

它并**不**真正把名字加入当前作用域，而是让编译器在查找名字时“顺便”去该命名空间里找（效果上相当于把该命名空间的成员提到最近的公共外层作用域）。

要点与坑：

1. **绝不要在头文件里写 `using namespace std;`**，会污染所有包含它的翻译单元。
2. 在函数内部使用相对安全，但仍可能导致二义性。
3. 与 using 声明不同，using 指令的效果是**传递性**的（`using namespace A;` 连 A 里再写的 `using namespace C;` 也一并生效），且对限定查找、非限定查找、ADL 的影响各不相同，容易产生意外的结果：

```cpp
namespace A { struct X {}; void f(X); }

namespace B {
    using namespace A;          // 在 B 内部“借用” A 的名字
    void f(double);
    void g(X x) {               // X 解析为 A::X
        f(x);                   // 普通查找在 B 中就找到 f → 停止，只得到 B::f(double)；
                                // 再叠加 ADL（X 属于 A）加入 A::f(X)；
                                // 重载决议选 A::f(X)（精确匹配优于 double 转换）
    }
}

void h() {
    B::X x;                     // 合法：限定查找会考虑 B 中的 using 指令
    f(x);                       // 只能靠 ADL 找到 A::f；
                                // 全局作用域不会因 B 的 using 指令而看到 A 的名字
}
```

4. 常见实践：在 `.cpp` 里可以用，在头文件里用命名空间别名或全限定名。

## 四、类型别名与别名模板

### 1. 基本别名

```cpp
using Int      = int;
using Callback = void(*)(int, double);
using StringMap = std::map<std::string, std::string>;
```

与 `typedef` 完全等价（同一类型），但**可读性更好**，尤其是指针/函数指针/数组：

```cpp
typedef void (*FnPtr1)(int);     // 名字藏在中间
using   FnPtr2 = void(*)(int);   // 名字在前，直观

typedef int Arr1[10];
using   Arr2 = int[10];
```

### 2. 别名模板（typedef 做不到）

```cpp
template <class T>
using Vec = std::vector<T>;

template <class T, class Alloc = std::allocator<T>>
using MyList = std::list<T, Alloc>;

Vec<int> v;                     // == std::vector<int>
```

### 3. 别名模板 + 依赖名（`typename` 的替代）

在模板里写 `typename T::value_type` 很啰嗦，可用别名模板简化：

```cpp
template <class T>
using value_type_t = typename T::value_type;

template <class T>
void f(T& c) {
    value_type_t<T> x{};        // 不必再写 typename
}
```

### 4. 别名模板不能被特化

```cpp
template <class T> using Alias = T;
// template <> using Alias<int> = double;   // 错误：别名模板不能特化
```

若需要特化，应使用类模板 + 继承/`std::conditional` 等技巧。

### 5. 与 `typedef` 的差异总结

| 对比项                         | `typedef`        | `using`             |
| ------------------------------ | ---------------- | ------------------- |
| 模板别名                       | 不支持           | 支持                |
| 可读性（复杂类型）             | 差（名字在中间） | 好（`名字 = 类型`） |
| 语义                           | 同一类型的别名   | 完全相同            |
| `typeid` / 重载决议 / 类型特征 | 一致             | 一致                |
| 能否被特化                     | 否               | 否                  |
| 写法风格                       | C 风格           | 现代 C++ 推荐       |

> 重要观念：`using A = B;` 与 `typedef B A;` 引入的是**同一个类型**，不是新类型。想造“强类型别名”要写 `struct A : B {}` 或用 `enum class`。

## 五、继承构造函数

```cpp
struct Base {
    Base(int);
    Base(int, double);
    Base(const std::string&);
};

struct Derived : Base {
    using Base::Base;   // 继承所有构造函数
    // 编译器生成：Derived(int) : Base(int) {} 等
};
```

要点：

1. 仅是“转发”到基类构造，派生类自己新增的成员用默认初始化。
2. 若派生类有自己的构造函数与之一致，会覆盖继承来的那个。
3. 拷贝/移动构造函数不会被继承（它们本就由编译器生成）。
4. 基类的默认构造函数不会被 `using` 继承——派生类默认构造仍需基类可默认构造。
5. 基类构造函数的**默认实参不会被继承**：
   - C++11/14：`using Base::Base;` 后，对应派生类构造函数**没有**默认实参，`Derived d(1);` 对 `Base(int, int = 0)` 会编译失败。
   - C++17 起（P0136）：编译器会为“带默认实参的基类构造函数”**额外生成多个重载**来模拟默认实参，`Derived d(1);` 恢复可用。
   - 但如果默认实参引用的是**派生类新增成员**，则无法工作（基类看不到派生类成员）。
6. `using Base::Base;` **不能**加 `explicit` 修饰，也不能单独 `= delete`；基类构造函数是 `explicit` 的，继承后仍是 `explicit`。
7. 有继承构造函数时，编译器仍会生成默认构造函数（若基类可默认构造），两者不冲突。

## 六、`using enum`（C++20）

把枚举的所有枚举量引入当前作用域，免去 `Color::Red` 前缀：

```cpp
enum class Color { Red, Green, Blue };

void f() {
    using enum Color;
    Color c = Red;          // 不必写 Color::Red
    switch (c) {
        using enum Color;   // 也可放在 switch 里，case 直接写 Red
        case Red:  break;
        case Green: break;
        case Blue: break;
    }
}
```

对比 `using Color::Red;`（C++11 起可对 scoped enum 的单个枚举量使用 using 声明）：`using enum` 一次性引入全部。

## 七、`using` 在类模板中的其他用法

### 1. 引入基类的依赖类型名

在模板继承中，基类的嵌套类型是**依赖名**，需 `typename`，也可用 using 声明“钉住”名字：

```cpp
template <class T>
struct Base {
    using value_type = T;
    void foo();
};

template <class T>
struct Derived : Base<T> {
    using Base<T>::value_type;   // 让 value_type 在本作用域可见
    using Base<T>::foo;          // 引入依赖成员函数名

    value_type get() { foo(); return {}; }
};
```

### 2. 用于 SFINAE / 检测惯用法

```cpp
template <class T>
using has_foo_t = decltype(std::declval<T>().foo());

template <class T, class = void>
struct has_foo : std::false_type {};

template <class T>
struct has_foo<T, std::void_t<has_foo_t<T>>> : std::true_type {};
```

## 八、常见错误与注意事项

1. **头文件中 `using namespace std;`** —— 污染全局，禁止。
2. **`using` 声明与同名不同类型冲突会报错**：
   ```cpp
   using Int1 = int;
   using Int1 = double;   // 错误：重定义
   ```
   但同名同类型重复声明是允许的。
3. **using 声明不能用来“重命名”**，它只是引入：
   ```cpp
   using std::cout;   // 名字仍叫 cout
   ```
4. **using 指令在类作用域中不允许**：`struct S { using namespace std; };` 错误。
5. **`using Base::Base;` 与虚继承**：虚基类的构造函数不会被最派生类以外的地方调用，继承构造可能带来目标类型限制，需谨慎。
6. **别名模板不支持偏特化**，若需要请用 `struct` 包装。
7. **使用 `using` 提升访问权限后**，该名字在派生类中的访问级别以 using 所在位置说明符为准。
8. **ADL 与 using 声明**：using 声明引入的名字会参与普通查找，但不影响 ADL 的候选集。

## 九、实战示例

```cpp
#include <iostream>
#include <memory>
#include <vector>

// 1. 别名模板
template <class T>
using Ptr = std::unique_ptr<T>;

template <class T>
using Vec = std::vector<T>;

// 2. 基类
struct Shape {
    virtual ~Shape() = default;
    virtual void draw() const = 0;
    void reset() { std::cout << "Shape::reset\n"; }
};

// 3. 继承构造 + 成员引入
struct Circle : Shape {
    using Shape::reset;              // 重新暴露（这里本就 public，仅示范）
    explicit Circle(double r) : r_(r) {}
    void draw() const override { std::cout << "circle " << r_ << "\n"; }
    double r_;
};

// 4. 恢复重载
struct Logger {
    void log(int);
    void log(const char*);
};
struct TaggedLogger : Logger {
    using Logger::log;               // 避免隐藏
    void log(double);                // 与上面构成重载
};

int main() {
    Vec<int> v{1, 2, 3};             // std::vector<int>
    Ptr<Circle> c = std::make_unique<Circle>(1.5);

    using std::cout;                 // 只引入 cout

    c->draw();
    c->reset();
    v.push_back(4);
    cout << v.size() << "\n";
}
```

### 补充：`using enum` 的完整可编译示例

```cpp
enum class Color { Red, Green, Blue };

const char* name(Color c) {
    switch (c) {
        using enum Color;            // C++20：case 里直接写 Red/Green/Blue
        case Red:   return "red";
        case Green: return "green";
        case Blue:  return "blue";
    }
    return "unknown";
}

int main() {
    using enum Color;                // 引入全部枚举量
    Color c = Green;                 // 等价于 Color::Green
    (void)c;
    return name(c) != nullptr ? 0 : 1;
}
```

## 十、进阶专题

### 1. using 与 `decltype` 组合做返回类型推导

```cpp
template <class Container>
using value_t = std::decay_t<decltype(*std::begin(std::declval<Container&>()))>;

template <class Container>
auto sum(const Container& c) -> value_t<Container> {   // 无需手写 typename
    value_t<Container> s{};
    for (auto&& x : c) s += x;
    return s;
}
```

别名模板把一长串 `typename ... ::value_type` 藏起来，让签名更清爽。

### 2. 用 using 声明限定运算符/成员模板

```cpp
struct Base {
    template <class T> void set(T);
    int  operator[](int);
};

struct Derived : Base {
    using Base::set;                  // 引入成员函数模板（整个模板）
    using Base::operator[];           // 引入重载运算符
};
```

注意：`using Base::operator=` **不会**改变编译器生成派生类赋值运算符的规则；若自己写了 `operator=`，必须显式再 `using Base::operator=` 才能同时保留基类版本。

### 3. using 与标号、枚举量的单点引入

```cpp
namespace cfg {
    constexpr int kWidth = 1280;
    enum class Mode { Fast, Safe };
}

constexpr auto W   = cfg::kWidth;      // 用变量（更常见于常量）
using cfg::Mode;                       // 引入类型名
using cfg::Mode::Fast;                 // C++11 起可引入单个枚举量
```

### 4. using 在 `switch` / `case` 中的位置

C++20 `using enum` 放在 `switch` 的复合语句开头时，作用域覆盖该 `switch` 内**所有** `case` 标签，因此 `case Red:` 可直接写（见上一节）。它的作用域就是所在的复合语句：如果写成 `case X: { using enum Color; ... }`，就只在该大括号内有效：

```cpp
switch (c) {
    case Color::Red: {
        using enum Color;              // 仅在此块内有效
        if (c == Red) { /* ... */ }
        break;
    }
    default: break;
}
```

### 5. using 修饰成员函数指针与 `std::function`

```cpp
struct S { void f(int); };

using PMem = void (S::*)(int);          // 成员函数指针类型
PMem p = &S::f;

using Fn = void(*)(int);                // 普通函数指针类型
using FnCallback = std::function<void(int)>;   // 也支持模板参数里的类型
```

### 6. using 与 C++20 concepts

别名模板可以作为 concept 的“辅助类型”，但**concept 只能用 `template <class T> concept` 定义，不能用 using 定义 concept**：

```cpp
template <class T>
using ref_t = T&;

template <class T>
concept CRef = requires(ref_t<T> r) { r + r; };   // OK
// template <class T> using CRef = ...;            // 错误：不能定义 concept
```

### 7. using 与 `std::variant` / `std::visit`（实践常见）

```cpp
#include <variant>
struct A { void hi() const; };
struct B { void hi() const; };
using V = std::variant<A, B>;

void greet(const V& v) {
    std::visit([](const auto& x) { x.hi(); }, v);
}
```

### 8. using 与内联命名空间（inline namespace）

内联命名空间的成员会**自动**被外层命名空间可见，和 `using namespace` 效果相似，但属于声明的一部分，推荐用于版本化库 API：

```cpp
namespace lib {
    inline namespace v2 {
        void run();                 // 外部可直接写 lib::run()
    }
    // 老版本仍在 lib::v1::run()
}
```

`using namespace lib::v2;` 达不到同样的“类型身份一致”效果，所以库设计优先用 `inline namespace`。

### 9. `using std::swap;` —— 最重要的惯用法

泛型代码里交换两个值时，正确写法是**同时**引入 `std::swap` 并依赖 ADL 找到用户自定义 swap：

```cpp
template <class T>
void my_sort(T& a, T& b) {
    using std::swap;        // 让 std::swap 成为候选
    if (b < a) swap(a, b);  // 若 T 所在命名空间有更好的 swap(T&, T&)，
                            // ADL 会优先选中它（比 std::swap 更匹配/更高效）
}
```

若写成 `std::swap(a, b);`，就**固定**调用标准版本，可能错过自定义的高效实现（如 `std::vector` 的 O(1) swap）。

### 10. 命名空间别名 ≠ using 指令

```cpp
namespace fs = std::filesystem;      // 别名：给命名空间起短名
using namespace std::filesystem;     // 指令：污染当前作用域
```

| 对比         | 命名空间别名 `namespace x = y;` | using 指令 `using namespace y;` |
| ------------ | ------------------------------- | ------------------------------- |
| 是否引入名字 | 否，仍需 `x::name`              | 是，名字可直接使用              |
| 头文件中使用 | 安全                            | 危险                            |
| 典型用途     | 缩短长命名空间                  | 局部便利                        |

### 11. 常见面试题对照

| 问题                                           | 答案要点                                   |
| ---------------------------------------------- | ------------------------------------------ |
| `using namespace X;` 与 `using X::a;` 的区别？ | 前者是“查找提示”，后者真正把名字加入作用域 |
| 能否用 using 改变类型的 `typeid`？             | 不能，别名就是原类型                       |
| 如何恢复被派生类隐藏的基类重载？               | `using Base::foo;`                         |
| 如何把 protected 暴露成 public？               | `using Base::foo;` 放在 public 区          |
| 别名模板能偏特化吗？                           | 不能，需 class template                    |
| `using Base::Base;` 会影响拷贝/移动构造吗？    | 不会，拷贝/移动由编译器单独生成            |
| `using enum` 是哪个标准？                      | C++20                                      |

## 十一、速查表

```cpp
using std::size_t;                    // 引入单个名字
using namespace std;                  // 引入整个命名空间（头文件禁用）
using Int = int;                      // 类型别名
template<class T> using Vec = std::vector<T>;   // 别名模板
using Base::Base;                     // 继承构造函数
using Base::foo;                      // public: 区 → 提升为 public（恢复被隐藏重载同理）
// private:   using Base::foo;       // 降级为 private（对 Derived 名字生效，可绕）
// using Base::x;                     // ❌ 非静态数据成员不可；静态成员 Base::s 可以
// using Base::Base; 放 private 区     // 继承构造函数也能降级（工厂 idiom）
using enum Color;                     // C++20：引入全部枚举量
using Color::Red;                     // 引入单个枚举量
```
